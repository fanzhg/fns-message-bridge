# 三个消息渠道的后台配置

共同步骤：创建机器人 → 将凭证填入 `config.toml` → 开启渠道 → `docker compose up -d` → 查询身份 → 填白名单 → `docker compose restart bridge` → 发送文本验收。
空白名单不保存普通文字，只处理 `/whoami` 或 `身份` 查询。

## Telegram

1. 私聊 **@BotFather**，发送 `/newbot`，创建专用机器人。
2. 将返回的 Token 填入 `[telegram].bot_token`，设 `enabled = true`。
3. 启动容器后，给机器人发送 `/start` 和 `/whoami`。
4. 将返回的数字 ID 填入 `allowed_users = ["你的ID"]`，重启容器。
5. 发送或转发一段文字，查看成功回复和 FNS 中的 `Inbox/telegram`。

使用专用机器人。程序发现已有 Webhook 会拒绝启动，不会擅自移除其他服务的 Webhook。
群消息受 Telegram 隐私模式和机器人权限影响，个人速记优先单聊。
服务器需能访问 `api.telegram.org`。需要代理时在 Compose 的 `environment` 中配置 `HTTPS_PROXY`，代理地址不要使用容器自身的 localhost。

## 钉钉

1. 在钉钉开发者后台创建你有权限管理的应用，添加**机器人能力**。
2. 配置名称、图标、介绍和可用范围，接收模式选择 **Stream**。
3. 获取 Client ID / Client Secret（部分界面为 AppKey / AppSecret）。
4. 按后台要求发布，使自己的账号在可用范围内。
5. 将凭证填入 `[dingtalk].client_id`、`client_secret`，设 `enabled = true`。
6. 启动/重启容器，单聊机器人发送 `身份`。
7. 将返回 ID 填入 `allowed_users`，重启容器，再发送普通文本。

优先使用 `senderStaffId`，不存在时程序使用 `senderId`。群聊需要 @ 应用机器人。
群设置中的“自定义 Webhook 机器人”只用于推送，不能用来接收本功能的消息。
钉钉的会话回复窗口过期后，重试仍能保存笔记，但可能无法补发成功确认，需在 FNS 网页检查。

## 飞书

1. 在飞书开放平台创建**企业自建应用**，开启机器人能力。
2. 获取 App ID（通常以 `cli_` 开头）和 App Secret。
3. 申请接收用户发给机器人的单聊消息权限；需要群聊时再申请接收群聊中 @ 机器人的消息权限。
4. 申请发送消息权限 `im:message:send_as_bot`，用于身份查询和保存确认。图片版还需要资源下载权限；在后台对应“获取消息中的资源文件”接口申请所需权限（`im:resource`，以及后台提示的消息读取权限）。
5. 事件与回调中订阅 **接收消息 v2.0**，事件类型 `im.message.receive_v1`。
6. 接收方式选择 **使用长连接接收事件**。
7. 填入 `[feishu].app_id`、`app_secret`，设 `enabled = true`，启动/重启容器。
8. 若后台要求先建立连接再保存订阅，在容器启动后完成订阅配置。
9. 创建并发布应用版本，使权限和事件生效，可用范围包含自己。
10. 单聊机器人发 `身份`，获得 `open_id`（通常以 `ou_` 开头），填入 `allowed_users`。
11. 重启容器，发送纯文本、图片、带图的富文本分别验收。新增权限需要发布应用版本。

群聊要将机器人加入群并 @ 它，不需要读取群内所有消息权限。
此配置对应中国版飞书；国际版 Lark 的域名未包含在当前版本中。

钉钉图片版需允许应用调用“下载机器人接收消息的文件内容”接口。程序优先使用回调中的 `robotCode`，没有时使用配置中的 `robot_code`，最后尝试 `client_id`。
若 v0.2.0 收到图片后报 `Invalid download URL`，且检查显示临时下载链接使用 HTTP，升级至 v0.2.1。此问题由程序的协议校验引起，无需重新申请权限。
TG 普通照片与以图片文件方式发送的原图均可接收，图片文件不保留用户原文件名，按日期时间命名。

## 每个渠道的验收

给机器人发普通文本 → 得到成功回复 → 在 FNS `你的仓库/Inbox/渠道` 看见笔记 → Obsidian 联网同步后看到同一篇笔记。
再检查换行文字、转发文字以及非白名单用户不产生笔记。
再发送图片，确认 MD 中可以显示图片，并确认超限图片不会回复保存成功。
成功回复表示 FNS 已保存，不表示每台设备都已完成同步。
